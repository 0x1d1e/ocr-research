# Implementation and evidence status

This is an implementation map, not a release checklist. The normative requirements are in the v4 specification. Passing software tests (297 passing tests in 20.1s under `OMP_NUM_THREADS=12`, Python 3.12, CPU) do not establish OCR quality, convergence, or deployment acceptance. "Implemented" below means the code path exists and is covered by software tests; it does not mean a release gate has passed.

| Area | State | Evidence or gap |
| --- | --- | --- |
| Annotation schema and JSONL page loading | Implemented | Schema validates IDs, geometry (finite non-boolean coordinates, positive winding, simple non-self-intersecting polygons, bounded vertex count), relations against the decoder's own candidate rules, table occupancy, provenance fields, image SHA-256 metadata, and exact reading-order membership. Loading verifies image bytes and that decoded image dimensions match the annotation. One image and annotation per row. |
| Corpus conversion, QA, and splitting | Implemented | Real corpus build completed via `scripts/build_real_corpus.py` across train (41,227 pages), val (8,043 pages), val-select (843 pages), and test (6,546 pages) from `paddlex_rec_dataset`, `khmerst-full`, and `DocLayNet`. The pipeline enforces transitive union-find grouping across documents, template families, image hashes, and source crops (`_group_records`, `_split_membership`), a strict split DAG hierarchy (`train -> val -> test`), and sequential crop hash exclusion (`exclude_crop_hashes`). Shard caching integrity tracks 12 configuration facets plus crop hash digests in `shard_fingerprint.json` and `.meta.json` sidecars. Manifest QA audit via `prismocr.data.tools qa` across `val-select.jsonl` (843 pages, 11,011 lines, 0 duplicate image hashes) and `train.jsonl` (41,227 pages, 387,134 lines) verifies structural integrity and split disjointness. `write_split_report` audits exact and character 3-gram transcript Jaccard overlap alongside exact/perceptual duplicate candidates. |
| Geometry and proposal matching | Implemented | Aspect-aware rotated boxes, rectangular Hungarian assignment, explicit quality acceptance using source-polygon IoU, candidate-overflow accounting, and center-aware proposal recovery that preserves dense adjacent lines without silent drops. Coordinate convention is recorded in `docs/spec-review.md`. |
| Backbone and text/region proposals | Implemented | Multi-scale anisotropic blocks, reparameterization, text heatmap, region queries, optional backbone activation checkpointing, and configurable top-down multiscale lateral fusion (`fused_text_head = true` by default in v4 training configs). Lateral fusion from f16 and f8 to f4 expands text-head receptive field from 23x55 px to 239x559 px (>100x area expansion) while maintaining the FP32 parameter byte inventory ceiling at 9.88MB (<10MB limit). No proposal-recall evidence on a real corpus exists. |
| Sparse OCR and CTC | Implemented | Compact per-bucket oriented strip sampling that gathers only selected lines (no per-line full-page feature-map copy), antipodal-orientation canonicalization, four sequence buckets, strict minimum CTC frame checks, Unicode codepoint vocabulary, and separate OOV accounting reporting `rejected_oov_line_count` (lines dropped from CTC due to OOV) and `oov_character_count` (total OOV codepoint occurrences). Character scores are explicitly uncalibrated. |
| Shared supervision and training entry point | Implemented | Detection, role, region, box, CTC, graph, and learned grid losses use forward-pass matches; heatmap supervision marks only the integer anchor cell; direct anchor-cell box/role supervision and bootstrap CTC embeddings ensure gradients when initial proposal scores are zero; role and graph losses are normalized by instance decisions (`role_terms` mean across supervised line roles and `graph_terms` mean across supervised candidate relations) rather than page count / batch size; ambiguous table grids are excluded from grid supervision with a log entry; graph supervision reuses the decoder's `relation_candidate_error`; `compose_recognition_pages` generates ground-truth `PARENT` relations to block container regions with verified geometric containment; `reading_order` supplies NEXT supervision when no explicit NEXT edges exist. Training supports linear warmup with cosine decay scheduling, threshold-free validation proposal ranking, CUDA AMP, gradient accumulation, activation checkpointing, and content-checked epoch-boundary resume. Checkpoint selection ranks inference-failure count first, then line-detection recall, then CER. No permissioned corpus or real-corpus convergence evidence is present. |
| Typed graph and reading order | Implemented | Public inference decodes typed NEXT, PARENT, KV_VALUE, RIGHT_CELL, and PARENT-derived CONTAINS relations, rejects decoder-invalid edges with reason codes, breaks cycles deterministically, keeps per-column reading-order scopes independent, and orders every line exactly once. Composed recognition pages generate geometrically verified ground-truth PARENT relations connecting lines to block container regions for structural graph supervision. |
| Tables | Implemented | The API assigns lines to cells, uses learned row/column indices plus learned `RIGHT_CELL` affinities to repair placement, infers geometric grids only as a fallback that merges small facing gaps, validates occupancy, preserves conflict status, and emits escaped HTML/Markdown. `compose_table_pages` provides synthetic table generation with exact table regions, grid cells, line-to-cell and cell-to-table PARENT relations, and RIGHT_CELL affinities, fully validated against schema v4.0. TEDS and exact-table evaluation are available. No table-quality evidence on a real corpus exists. |
| Python prediction API | Implemented | Model-bound calibration checks, coordinate inversion (`pixels`/`normalized`), typed graph/table decoding, overlapping high-resolution tiling, overflow retries with partial-result warnings, and duplicate stitching are integrated. Structured `INVALID_IMAGE`/`INFERENCE_ERROR` failures preserve stage metadata only by opt-in, and diagnostics exclude raw text and images by default. Scores stay `null` without a calibration artifact. |
| Validation-only calibration | Implemented | `prismocr.calibration` fits Platt scaling for text/region detector scores and for NEXT/PARENT/KV_VALUE/RIGHT_CELL relation scores using public inference at deployment thresholds, refuses to publish without split and model provenance, explicit-NULL/partial relation labels preserved, and reports precision/recall curves plus ECE/Brier reliability. Grid-head scores stay uncalibrated (`grid_scores_calibrated: false`). Synthetic tests verify the software paths; real-corpus calibration reliability is not established. |
| Evaluation and benchmark | Implemented | Manifest evaluation reports detection precision/recall per IoU threshold using source-polygon IoU, overall and language-sliced CER/WER with unmatched predictions as insertions, Khmer mark/coeng context metrics, graph relation precision/recall/F1, reading-order pairwise and exact-page accuracy, TEDS and exact-table accuracy, KV matching, and failure/overflow denominators. Reports flag zero-denominator metrics as undefined instead of implying success. The benchmark separates stages, reports per-stage execution counts and conditional scope, tensor bytes, export/checkpoint bytes separately, and process peak RSS. No release benchmark evidence is available. |
| ONNX/export | Implemented | Integrated full-model ONNX export with pinned opset/runtime matrix, external-weight checksums, fusion parity, recognizer-bucket coverage, full support and parity for both fused and unfused text heads across all sequence buckets, and a canonical decoded-document comparator covering lines, regions, cells, tables, relations with reason codes, reading order, warnings, overflow state, KV pairs, and relation scores. FP16 fusion parity proposal alignment (`_align_fusion_parity_outputs` canonicalizes proposal-indexed and relation outputs by sorted proposal index) and top-K boundary divergence handling in `prismocr/onnx_export.py` tolerate marginal float16 score drift at capacity boundaries while strictly rejecting non-marginal discrepancies. ONNX preserves unassigned cells, emits `CAPACITY_OVERFLOW`/`STRUCTURE_CAPACITY_OVERFLOW` and `RELATIONS_SUPPRESSED`, and maps preprocessing failures to `INVALID_IMAGE`. Verification is synthetic; no trained-artifact or target-runtime acceptance is claimed. |

## Project milestones

The roadmap to production release is organized into four sequential milestones:

- **Milestone 1: Corpus Built** (real corpus constructed with transitive group closure, strict split DAG hierarchy, and crop hash exclusion) — Complete
  - Real corpus build completed using `scripts/build_real_corpus.py` with transitive group closure, strict split DAG hierarchy (`train -> val -> test`), and sequential crop hash exclusion across train (41,227 pages), val (8,043 pages), val-select (843 pages), and test (6,546 pages) from `paddlex_rec_dataset`, `khmerst-full`, and `DocLayNet`. Shard caching integrity is enforced via `shard_fingerprint.json` tracking 12 configuration facets and crop hash digests.
- **Milestone 2: Labels QA'd** (manifest QA audit across real splits verifying disjointness and structural integrity) — Complete
  - Manifest QA audit completed via `prismocr.data.tools qa` across `val-select.jsonl` (843 pages, 11,011 lines, 0 duplicate hashes) and `train.jsonl` (41,227 pages, 387,134 lines), verifying split disjointness, declared dimension alignment, and structural integrity. Split report (`splits/split-report.json`) audits 2,517 independent groups, exact/perceptual duplicates, and character 3-gram transcript overlap.
- **Milestone 3: Model Trained** (v4 model architecture with default fused text head, anchor supervision, CTC warmup, and cosine schedule; awaiting multi-epoch training run)
  - Complete v4 model architecture (fused text head enabled by default expanding receptive field >100x area under the 10 MB FP32 parameter ceiling, direct anchor-cell box/role supervision, bootstrap CTC embeddings, linear CTC warmup, and cosine learning rate decay) and atomic checkpointing are implemented and tested; awaiting full-scale multi-epoch training run on the verified real corpus (`configs/v4_real_corpus.toml`).
- **Milestone 4: Model Validated** (release checkpoint evaluated against human-audited real test set and hardware latency profile)
  - Evaluation harnesses, Platt scaling calibration fitting, CPU ONNX export, and runtime benchmark suites are implemented. Final validation gate requires evaluating the Milestone 3 trained release checkpoint against the Milestone 2 QA'd real test set and verifying the target hardware latency/memory profile.

## Release evidence still required

A completed multi-epoch training run on the built real corpus (`configs/v4_real_corpus.toml`); real-corpus convergence; frozen vocabulary and validation-fitted thresholds/calibration; repeated training runs; quality and latency ablations; 6 GB GPU measurements; a complete FP32 tensor-byte inventory on the selected deployment artifact (the code enforces the 10,000,000-byte ceiling); and CPU PyTorch/ONNX parity on a pinned runtime matrix with the trained checkpoint.

The existing 297 passing tests establish software invariants and structural contracts only (including fused text head receptive field expansion, default `fused_text_head` training configuration, source crop lineage and sequential crop hash exclusion, strict split DAG hierarchy, FP16 fusion parity proposal alignment and top-K boundary handling, ground-truth PARENT relation supervision, shard caching integrity, decision-normalized role and graph losses, separate OOV accounting, schema-validated synthetic table page composition, and CI workflow dependency pinning via `requirements-lock.txt`). Synthetic rendering, a successful forward pass, synthetic training, or a checkpoint round trip is not evidence of Khmer/English recognition accuracy, real-corpus convergence, a 25% sparse speedup, CPU latency, or production readiness. Real corpus build (Milestone 1) and manifest QA audit (Milestone 2) are completed; multi-epoch model training (Milestone 3) and release validation on held-out test data (Milestone 4) remain pending. `save_artifact` deletes any existing calibration sidecar on a successful publication because calibration is bound to the prior weights; a failed publication rolls back and leaves the prior calibrated bundle loadable, so regenerate calibration after retraining.
