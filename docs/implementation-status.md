# Implementation and evidence status

This is an implementation map, not a release checklist. The normative requirements are in the v4 specification. Passing software tests do not establish OCR quality, convergence, or deployment acceptance. "Implemented" below means the code path exists and is covered by software tests; it does not mean a release gate has passed.

| Area | State | Evidence or gap |
| --- | --- | --- |
| Annotation schema and JSONL page loading | Implemented | Schema validates IDs, geometry (finite non-boolean coordinates, positive winding, simple non-self-intersecting polygons, bounded vertex count), relations against the decoder's own candidate rules, table occupancy, provenance fields, image SHA-256 metadata, and exact reading-order membership. Loading verifies image bytes and that decoded image dimensions match the annotation. One image and annotation per row. |
| Corpus conversion, QA, and splitting | Implemented | `prismocr.data.tools` converts ICDAR-style quadrilateral text (including quoted/unquoted commas in transcripts), checks schema/provenance/checksums and declared dimensions, reports exact and perceptual duplicate candidates, and creates deterministic document/template-family/image/near-duplicate grouped splits. Conversion still requires human label QA; other source formats and permission audits are not supplied. |
| Geometry and proposal matching | Implemented | Aspect-aware rotated boxes, rectangular Hungarian assignment, explicit quality acceptance using source-polygon IoU, candidate-overflow accounting, and center-aware proposal recovery that preserves dense adjacent lines without silent drops. Coordinate convention is recorded in `docs/spec-review.md`. |
| Backbone and text/region proposals | Implemented | Multi-scale anisotropic blocks, reparameterization, text heatmap, region queries, and optional backbone activation checkpointing. No proposal-recall evidence on a real corpus exists. |
| Sparse OCR and CTC | Implemented | Compact per-bucket oriented strip sampling that gathers only selected lines (no per-line full-page feature-map copy), antipodal-orientation canonicalization, four sequence buckets, strict minimum CTC frame checks, Unicode codepoint vocabulary, and visible OOV reporting. Character scores are explicitly uncalibrated. |
| Shared supervision and training entry point | Implemented | Detection, role, region, box, CTC, graph, and learned grid losses use forward-pass matches; heatmap supervision marks only the integer anchor cell; ambiguous table grids are excluded from grid supervision with a log entry; graph supervision reuses the decoder's `relation_candidate_error`; `reading_order` supplies NEXT supervision when no explicit NEXT edges exist. Training supports CUDA AMP, gradient accumulation, activation checkpointing, and content-checked epoch-boundary resume. Checkpoint selection ranks inference-failure count first, then line-detection recall, then CER. No permissioned corpus or real-corpus convergence evidence is present. |
| Typed graph and reading order | Implemented | Public inference decodes typed NEXT, PARENT, KV_VALUE, RIGHT_CELL, and PARENT-derived CONTAINS relations, rejects decoder-invalid edges with reason codes, breaks cycles deterministically, keeps per-column reading-order scopes independent, and orders every line exactly once. |
| Tables | Implemented | The API assigns lines to cells, uses learned row/column indices plus learned `RIGHT_CELL` affinities to repair placement, infers geometric grids only as a fallback that merges small facing gaps, validates occupancy, preserves conflict status, and emits escaped HTML/Markdown. TEDS and exact-table evaluation are available. No table-quality evidence on a real corpus exists. |
| Python prediction API | Implemented | Model-bound calibration checks, coordinate inversion (`pixels`/`normalized`), typed graph/table decoding, overlapping high-resolution tiling, overflow retries with partial-result warnings, and duplicate stitching are integrated. Structured `INVALID_IMAGE`/`INFERENCE_ERROR` failures preserve stage metadata only by opt-in, and diagnostics exclude raw text and images by default. Scores stay `null` without a calibration artifact. |
| Validation-only calibration | Implemented | `prismocr.calibration` fits Platt scaling for text/region detector scores and for NEXT/PARENT/KV_VALUE/RIGHT_CELL relation scores using public inference at deployment thresholds, refuses to publish without split and model provenance, explicit-NULL/partial relation labels preserved, and reports precision/recall curves plus ECE/Brier reliability. Grid-head scores stay uncalibrated (`grid_scores_calibrated: false`). Synthetic tests verify the software paths; real-corpus calibration reliability is not established. |
| Evaluation and benchmark | Implemented | Manifest evaluation reports detection precision/recall per IoU threshold using source-polygon IoU, overall and language-sliced CER/WER with unmatched predictions as insertions, Khmer mark/coeng context metrics, graph relation precision/recall/F1, reading-order pairwise and exact-page accuracy, TEDS and exact-table accuracy, KV matching, and failure/overflow denominators. Reports flag zero-denominator metrics as undefined instead of implying success. The benchmark separates stages, reports per-stage execution counts and conditional scope, tensor bytes, export/checkpoint bytes separately, and process peak RSS. No release benchmark evidence is available. |
| ONNX/export | Implemented | Integrated full-model ONNX export with pinned opset/runtime matrix, external-weight checksums, fusion parity, recognizer-bucket coverage, and a canonical decoded-document comparator covering lines, regions, cells, tables, relations with reason codes, reading order, warnings, overflow state, KV pairs, and relation scores. ONNX preserves unassigned cells, emits `CAPACITY_OVERFLOW`/`STRUCTURE_CAPACITY_OVERFLOW` and `RELATIONS_SUPPRESSED`, and maps preprocessing failures to `INVALID_IMAGE`. Verification is synthetic; no trained-artifact or target-runtime acceptance is claimed. |

## Release evidence still required

A permissioned, document-grouped Khmer/English corpus; converter coverage and human label QA; a reproducible v3 control; frozen vocabulary and validation-fitted thresholds/calibration; repeated training runs; quality and latency ablations; a frozen final split; 6 GB GPU measurements; a complete FP32 tensor-byte inventory on the selected deployment artifact (the code enforces the 10,000,000-byte ceiling); and CPU PyTorch/ONNX parity on a pinned runtime matrix with a trained model.

The existing tests establish software invariants only. Synthetic rendering, a successful forward pass, synthetic training, or a checkpoint round trip is not evidence of Khmer/English recognition accuracy, real-corpus convergence, a 25% sparse speedup, CPU latency, or production readiness. No real OCR training run was possible because no permissioned manifest/corpus was available in the inspected project and standard local data roots. `save_artifact` deletes any existing calibration sidecar on a successful publication because calibration is bound to the prior weights; a failed publication rolls back and leaves the prior calibrated bundle loadable, so regenerate calibration after retraining.
